Search debug report for plant-nursery
Date: 2026-09-22

Goal
- Inspect the current search algorithm for queries around shade, low watering, and small gardens.
- Check how Gemini Flash intent parsing and the backend retrieval/ranking behave in practice.

Current search path in the app
1. Gemini Flash parses the user query into a structured intent.
2. The backend derives search expansions and filters from that intent.
3. If the query strongly signals watering needs, the riego-specific branch can run first.
4. Otherwise the backend falls back to category matching, exact attribute matching, and hybrid search.
5. Final ranking is returned from Postgres-backed retrieval, not from Gemini alone.

Important observation
- The current logic is good at recognizing "poco riego" / "sombra" as care signals.
- It is weaker at handling the combination of shade + low water + small garden when the query does not explicitly name a category like "árbol".
- In those cases, the top results are often drought-tolerant plants, but not always shade-tolerant ones.
- The search still returns relevant plants in the broad sense, but the ordering is not yet optimal for the full intent.

Summary of what is working
- Gemini Flash is successfully extracting care-related signals in many cases.
- The backend correctly returns low-water species in the results.
- Explicit category hints such as "arbol" improve relevance noticeably.
- After adding the query-aware rerank layer, the ordering improved for mixed queries.
- Small-garden queries now surface compact plants earlier instead of leading with large trees.

Summary of what is failing
- Shade and low-water are still not perfectly balanced for the first query, but the worst mismatches are reduced.
- Native intent is still not consistently extracted as a hard filter.
- Some large trees remain present for broad queries that do not name a category, but they are no longer dominating the top positions as much.

Practical conclusion
- The current algorithm is usable, but it needs better intent-to-ranking translation for combined constraints.
- The biggest improvement opportunity is to add a rerank layer or stronger scoring for:
  - exposure match
  - low-water match
  - size/compactness match
  - native filter when the query explicitly asks for native plants
- The rerank layer is the correct direction for this codebase because the raw retrieval branches are already useful, but they need a final normalization step when multiple constraints appear together.

Suggested next improvement
- Add a rerank step for complex queries that scores top candidates against the combined intent instead of relying mostly on retrieval order.
- Prioritize candidates that satisfy all of these simultaneously when present:
  - shade or semisombra
  - bajo riego
  - compact size for small gardens
  - native if requested
